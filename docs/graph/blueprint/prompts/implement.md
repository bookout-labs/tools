# Implement the slice

Edit the owned worktree in the attempt container within the cleared slice and its acceptance.
Read the related repository checkouts when the plan's assumptions cite them. Run the contract's
check command, which includes the accepted tests, and fix concrete failures within the allowance.
Never edit, delete or skip the accepted tests or an existing test, and never change the check
command, CI workflows, the verify skill or the contract file, except the protected files your slice
names. A revert slice may delete the tests its merge commit added. If the code contradicts a fact the
plan states, do not build it. Ask a question that cites the plan fact and the code. On a first
attempt whose acceptance already holds on the pinned base, edit nothing and set no_change to the
checks you ran and what they showed. With any edit, a repair or a human_question, leave no_change
null. A clean tree without that evidence is an invalid answer. On a repair, address the evidenced
findings, failed checks, failed criteria or surviving mutations on the existing PR. For a surviving
mutation, add a test that notices it, or name it as equivalent with the reason no test can notice
it. Summarize the actual edits and checks. Foreman verifies the final tree, commits and publishes.

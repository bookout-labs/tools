Where Foreman works

The human works through a coordinator or personal agent. The agent files the GitHub issue and posts the human's answers, comments, plan approvals and stop requests as issue comments under the human's identity.

Foreman runs from bookout-labs/tools. Each issue names the repository where its changes belong. The Project board mirrors the run state and shows the result on the card. GitHub, the CARR record layer and T3 hold shared context. Git versions the blueprint.

Scope, recovery and checks

Read target_repository issue and dependencies. Update the issue's run label and status comment. No repository edits or PR writes.

Missing child payload stops admission. A pstack pin that can't be fetched or exported stops admission with skill_missing, an issue whose identity differs from the assignment with invalid_output, and a GitHub or checkout failure with git_failed. An open dependency leaves the issue unadmitted. Worker dispatch failures use shared dispatch. The human's answer resumes route.

  • GitHub repository identity and run configuration agree.
  • Open dependencies prevent admission and later eligibility is read from GitHub.
